## 维护规则

- 用户可见行为修改前，先更新对应的权威设计文档和实施计划。
- 数据结构、同步、备份或恢复变化必须先更新数据架构，并单独取得生产授权。
- 已完成的日期化设计和实施计划由 Git 历史保存，不在工作树重复归档。
- 不得为了减少文件数量而删除迁移、旧数据兼容、同步保护或恢复路径。
- 构建产物、依赖、缓存和本地工具保持在 `.gitignore` 中，不作为项目源文件提交。
- 文档不记录密钥、令牌、用户数据、私有备份位置或可识别用户的生产证据。

## 当前实施计划

1. 收敛来源导入确认表单：不显示或保存来源网址、拼配组成和拼配说明，同时保留旧数据兼容字段。
2. 将全部 Edge Function 测试纳入部署门禁，并保持数据库安全测试不变。
3. 仅升级有安全公告或明确补丁收益的依赖，锁文件变更后重新执行全套验证。
4. 版本化 PWA 运行时缓存并拆分公共依赖，避免旧哈希资源长期累积和主入口过大。
5. 统一导出文案、清理无入口烟雾页，并在手机尺寸、单元测试、Edge 测试、Lint 和生产构建通过后提交。
