## 维护规则

- 用户可见行为修改前，先更新对应的权威设计文档和实施计划。
- 数据结构、同步、备份或恢复变化必须先更新数据架构，并单独取得生产授权。
- 已完成的日期化设计和实施计划由 Git 历史保存，不在工作树重复归档。
- 不得为了减少文件数量而删除迁移、旧数据兼容、同步保护或恢复路径。
- 构建产物、依赖、缓存和本地工具保持在 `.gitignore` 中，不作为项目源文件提交。
- 文档不记录密钥、令牌、用户数据、私有备份位置或可识别用户的生产证据。
- 进行中的跨模块整改记录在 [当前实施计划](implementation-plan.md)；完成后把稳定结论合并回权威文档并由 Git 历史保存计划。
