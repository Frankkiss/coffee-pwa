# 图片来源导入设计

日期：2026-06-14

## 目标

在现有“来源导入”能力上增加图片导入。淘宝、天猫和部分烘焙商页面经常把咖啡豆核心信息放在商品详情图里，因此第一版需要允许用户上传截图或详情长图，并把图片里的文字转成可解析文本。

## 方案

第一版采用“本地 OCR + DeepSeek 结构化解析”的过渡方案：

1. 用户在“来源导入”里选择商品详情图、截图或长图。
2. 前端在浏览器本地运行 OCR，把图片文字识别出来。
3. 识别结果追加到“商品详情文本”输入框，用户可以手动修正。
4. 用户点击“AI 解析”，继续调用现有 Supabase Edge Function。
5. Edge Function 只接收文本和可选来源链接，再调用 DeepSeek 输出豆子字段草稿。
6. 前端展示导入预览，用户确认后才保存到豆仓。

## 多模态预留

本地 OCR 只是临时输入层。后续 DeepSeek 官方 API 提供稳定可用的多模态图片输入后，可以把“图片转文字”这一步替换为服务端多模态解析：

- 前端仍保留相同的图片入口。
- 后端新增或扩展 Edge Function 接收图片或图片引用。
- DeepSeek 多模态直接从图片抽取豆子信息。
- 前端仍使用现有导入预览和确认保存流程。

这次不实现 DeepSeek 多模态，也不把图片上传到 DeepSeek。

## 数据与隐私

- 默认不上传、不保存原图。
- 默认备份仍只包含文本数据，不包含图片。
- OCR 结果只是辅助文本，用户可编辑。
- AI 解析结果仍是草稿，必须用户确认后才写入豆仓。
- DeepSeek API Key 仍只存在 Supabase Edge Function 环境变量中。

## 用户界面

在“来源导入”区域增加一个图片导入块：

- 图片选择按钮，支持 `image/*`。
- 已选择图片文件名。
- “识别图片文字”按钮。
- OCR 运行状态和错误提示。
- 识别完成后，把文字追加到商品详情文本框。

界面文案需要说明：原图不会保存，只把识别出的文字用于 AI 解析。

## 错误处理

- 未选择图片时，不允许开始 OCR。
- OCR 识别为空时提示用户换一张更清晰的图，或手动粘贴文字。
- OCR 失败时保留当前已输入文本，不清空用户内容。
- DeepSeek 解析失败时沿用现有错误提示和草稿保护逻辑。

## 验收标准

1. 用户可以选择一张图片并触发 OCR。
2. OCR 结果会追加到商品详情文本框，而不是覆盖已有文本。
3. OCR 结果可以继续通过现有 DeepSeek 来源导入流程生成草稿。
4. 原图不会写入 Supabase、JSON 备份或 CSV 导出。
5. 代码为未来 DeepSeek 多模态保留清晰替换点。
6. 测试、构建和密钥扫描通过。
