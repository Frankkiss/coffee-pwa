# IndexedDB 只读缓存 v1 设计

## 目标

为咖Day增加手机弱网可用性：用户在线登录并成功读取云端数据后，应用把豆仓和冲煮记录保存到本机 IndexedDB。之后如果断网或 Supabase 读取失败，应用可以显示最近一次成功缓存的数据。

## 范围

本版本只做只读缓存：

- 缓存咖啡豆列表。
- 缓存冲煮记录列表。
- 首页概览、豆仓列表、冲煮记录列表可以从缓存降级读取。
- UI 明确提示“正在显示离线缓存”，避免用户误以为数据已经实时同步。

本版本不做：

- 离线新增咖啡豆。
- 离线编辑或删除。
- 离线冲煮记录提交。
- 自动同步队列。
- 冲突合并。
- 图片缓存或图片备份。

## 数据策略

云端 Supabase 仍是登录用户的数据源。IndexedDB 只是本机最近一次成功读取后的副本。

缓存单位：

- `beans`：保存当前用户可见的未删除咖啡豆。
- `brewLogs`：保存当前用户可见的未删除冲煮记录。

每份缓存包含：

- `userId`：避免不同登录用户混用缓存。
- `updatedAt`：缓存更新时间。
- `rows`：实际数据。

读取策略：

1. 优先请求 Supabase。
2. 请求成功后写入 IndexedDB，并显示云端数据。
3. 请求失败时读取同一用户的 IndexedDB 缓存。
4. 如果有缓存，显示缓存并提示离线状态。
5. 如果没有缓存，显示原始错误。

## UI 行为

首页：

- 保持当前首页概览布局。
- 如果来自缓存，显示“离线缓存”状态。
- 若缓存为空，仍显示空态。

豆仓：

- 读取失败但有缓存时，显示缓存豆子。
- 在状态提示中说明这些数据来自本机缓存，新增/编辑仍需要联网。

冲煮记录：

- 读取失败但有缓存时，显示缓存记录。
- 在状态提示中说明这些数据来自本机缓存。

## 实现边界

新增 `app/src/features/offline/` 目录，集中放 IndexedDB 缓存逻辑，避免分散到各业务组件。

核心函数：

- `buildOfflineCacheSnapshot(rows, userId, now)`：生成缓存快照。
- `isOfflineCacheForUser(snapshot, userId)`：确认缓存归属。
- `writeOfflineCache(kind, snapshot)`：写入 IndexedDB。
- `readOfflineCache(kind, userId)`：读取当前用户缓存。

## 测试

优先测试不依赖浏览器 IndexedDB 的纯逻辑：

- 缓存快照会记录 `userId`、`updatedAt` 和 rows。
- 当前用户只能读取自己的缓存快照。
- 空缓存或其他用户缓存不会被当作可用数据。

IndexedDB 读写通过 TypeScript build 和浏览器运行验证覆盖。

## 风险

- 浏览器隐私清理可能删除 IndexedDB，所以文件导出备份仍必须保留。
- 只读缓存不能替代云端同步，离线期间的新增/编辑仍会失败。
- 后续做离线写入时，需要单独设计待同步队列和冲突处理。
