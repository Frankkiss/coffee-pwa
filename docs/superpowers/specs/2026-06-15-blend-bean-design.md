# 拼配咖啡豆设计补充

日期：2026-06-15

## 背景

豆仓第一版默认一支豆子对应单一产地、单一处理法和单一品种。但实际购买的烘焙豆可能是拼配豆，尤其是多产区、多处理法或不同烘焙度组合。若继续只用一个 `origin` 字段表达拼配，会让相似豆推荐和 AI 推荐误判。

## 目标

- 新增咖啡豆时可以标记为 `单一产区` 或 `拼配豆`。
- 拼配豆支持一个“拼配说明”文本框，便于手机端粘贴豆袋、淘宝详情或烘焙商文案。
- 来源导入和 OCR + AI 解析可以返回结构化拼配组成草稿。
- 推荐逻辑识别拼配豆，不再只按单一产地完全相同判断。

## 数据结构

`beans` 增加字段：

- `bean_type text not null default 'single_origin'`
  - `single_origin` 表示单一产区或 SOE。
  - `blend` 表示拼配豆。
- `blend_components jsonb not null default '[]'::jsonb`
- 每个组成可包含 `origin`、`process`、`variety`、`percentage`、`role`、`notes`。`percentage` 是可选辅助字段，不是必填字段。
- `blend_notes text`
  - 保存用户原始拼配说明，便于以后回看原始文案。

前端类型用 `BeanBlendComponent[]` 表达结构化组成。旧数据默认视为 `single_origin`，不破坏已有记录。

## 表单设计

豆仓表单新增：

- 类型选择：单一产区 / 拼配豆。
- 当选择拼配豆时显示“拼配说明”文本框。
- 文本框支持自然语言输入，例如：

```text
60% 巴西 日晒 黄波旁，提供坚果和甜感
40% 埃塞俄比亚 水洗 原生种，提供花香和柑橘
```

第一版不做复杂编辑器。前端会尽量从每行中识别比例；没有比例时也会保留产地、处理法、品种和备注。AI 导入时可以直接填充结构化组成，并回填为可编辑文本。

## 推荐影响

规则推荐做以下调整：

- 拼配豆与拼配豆之间，如果组成产地、处理法或风味标签有重合，应增加相似度。
- 拼配豆只有在明确填写比例时才判断主次；比例未知时，不猜测哪一支豆是主体。
- 模板推荐不只看 `bean.process`，也会看拼配组成里的处理法；例如拼配里有日晒和巧克力/坚果标签时，更容易选甜感、稳定、低苦模板。
- AI 推荐上下文会包含 `bean_type`、`blend_components` 和 `blend_notes`，并要求 AI 说明“这是拼配豆，建议如何平衡已知组成带来的甜感、香气、酸质和厚度”。比例未知时，AI 必须明确采用保守均衡试冲，不按比例加权。

## 来源导入影响

DeepSeek 来源导入提示词增加字段：

- `beanType`
- `blendComponents`
- `blendNotes`

如果商品详情写明“拼配、Blend、配方豆、多产区”等信息，AI 应返回 `beanType: "blend"`，并尽量拆成多个组成。来源导入结果仍只是草稿，用户确认后才写入豆仓。

## 备份与导出

- JSON 备份直接包含新增字段。
- CSV 豆仓导出增加 `豆子类型` 和 `拼配组成` 两列。
- 默认备份仍为轻量文本数据，不包含图片。

## 非目标

- 不做拼配比例图表。
- 不做多行复杂组件编辑器。
- 不自动联网查询拼配配方。
- 不让 AI 覆盖用户已确认的拼配组成。
