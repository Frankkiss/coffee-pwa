# 安卓优先咖啡豆仓与冲煮日志 PWA 设计草案

日期：2026-06-12

## 目标

制作一款个人长期使用的咖啡工具，优先服务安卓手机。第一版采用本地优先 PWA，不做蓝牙秤、账号系统、社区分享或复杂设备生态。核心目标是稳定记录咖啡豆信息、冲煮记录，并根据历史记录推荐新豆的冲煮方案。

第一版必须保证数据可导出、可恢复、可迁移。云同步作为第二版预留，不在第一版实现。

## 使用场景

用户在手机上打开已安装到桌面的 PWA，完成以下操作：

1. 录入一支新咖啡豆，包括处理法、产地、品种、处理站、海拔、烘焙日期和风味信息。
2. 每次冲煮后记录器具、研磨度、水温、粉水比、时间、评分和口感反馈。
3. 准备冲煮新豆时，输入豆子信息，系统根据历史相似豆子和高评分记录推荐可尝试的方案。
4. 定期导出轻量备份，必要时从备份文件恢复数据。

## 第一版范围

### 必做功能

- 豆仓管理：新增、编辑、删除、搜索、筛选咖啡豆。
- 冲煮日志：新增、编辑、删除、查看每次冲煮记录。
- 风味与评分：记录酸、甜、苦、涩、醇厚度、余韵、整体评分和文字备注。
- 相似豆推荐：根据处理法、产地、品种、烘焙度、风味标签、海拔和历史评分推荐方案。
- 本地存储：使用 IndexedDB 保存核心数据。
- PWA 安装：支持安卓 Chrome 添加到主屏幕。
- 离线使用：无网时仍能打开、录入和查看数据。
- 备份恢复：支持 JSON 完整数据导出、JSON 导入恢复、CSV 导出。

### 暂不实现

- 蓝牙秤连接。
- iOS 原生 App。
- 微信小程序。
- 用户账号登录。
- 云同步。
- 社区分享。
- 自动抓取全网豆子资料。
- 复杂 AI 推荐。

## 页面结构

### 首页

首页服务于手机快速操作，显示：

- 新增冲煮记录按钮。
- 新增咖啡豆按钮。
- 最近冲煮记录。
- 当前豆仓摘要。
- 上次导出备份时间。
- 备份提醒。

### 豆仓

豆仓展示所有咖啡豆，可按状态、处理法、产地、烘焙商、风味标签筛选。

单支豆子字段：

- 名称。
- 烘焙商。
- 产地。
- 庄园或处理站。
- 处理法。
- 品种。
- 海拔。
- 烘焙日期。
- 烘焙度。
- 风味标签。
- 净含量。
- 剩余量。
- 购买价格。
- 购买日期。
- 豆袋照片或压缩图片。
- 备注。

### 冲煮日志

每条冲煮记录绑定一支咖啡豆。

字段：

- 咖啡豆 ID。
- 冲煮日期。
- 器具。
- 滤纸。
- 磨豆机。
- 研磨度。
- 粉量。
- 水量。
- 粉水比。
- 水温。
- 总时间。
- 注水阶段。
- 口感评分。
- 酸、甜、苦、涩、醇厚度、余韵。
- 风味标签。
- 是否钉为推荐方案。
- 备注。

### 推荐

用户选择或录入一支新豆后，系统计算历史记录相似度，并给出推荐方案。

推荐结果包括：

- 推荐粉水比。
- 推荐水温。
- 推荐研磨度。
- 推荐总时间。
- 推荐器具。
- 推荐理由。
- 参考的历史记录。

第一版推荐逻辑必须可解释，不使用黑箱判断。

## 推荐算法第一版

第一版使用规则评分：

```text
相似度 =
处理法匹配 * 25
产地匹配 * 20
品种匹配 * 15
烘焙度匹配 * 15
风味标签重合 * 15
海拔接近 * 5
烘焙日期阶段接近 * 5
```

推荐时优先选择相似度高且评分高的历史冲煮记录。展示推荐理由时，要明确说明来自哪些相似记录。

## 数据安全与备份

数据安全是第一版核心功能。

### 本地数据

核心数据保存在浏览器的 IndexedDB 中。IndexedDB 适合保存结构化数据，比 localStorage 更适合长期记录豆仓、冲煮日志和备份元数据。

### 轻量备份

默认备份为轻量 JSON 文件，只包含文字数据、参数、风味标签、评分、备注和元数据，不包含图片。

导出文件命名：

```text
coffee-backup-YYYY-MM-DD.json
```

该备份通常很小。即使包含 100 支豆子和 1000 条冲煮记录，预计大致在 1 MB 到 5 MB 量级，具体取决于备注长度。

### 图片备份

图片不进入默认备份。用户手动选择“完整备份”时，才包含压缩后的图片或缩略图。

不保存原图。上传或拍摄图片后，应用应压缩为适合查看的尺寸，减少长期存储压力。

### 自动快照

应用内部保留最近 5 个本地快照。触发条件：

- 导入备份前。
- 删除咖啡豆前。
- 批量修改前。
- 数据结构升级前。

超过 5 个快照后删除最旧快照，避免占用过多空间。

### 备份提醒

首页显示上次手动导出备份时间。超过 7 天未导出时提醒用户备份。

### 恢复

恢复流程必须在覆盖数据前创建本地快照。导入时检查 schemaVersion，发现版本不匹配时走迁移逻辑。

### 导出格式

第一版支持：

- JSON：完整恢复使用。
- CSV：用于 Excel、Notion 或其他工具查看。

## 第二版预留

第一版数据结构必须为云同步预留字段：

```text
id
createdAt
updatedAt
deletedAt
schemaVersion
deviceId
syncStatus
lastSyncedAt
```

第二版可选方向：

- WebDAV 文件备份。
- Supabase 云数据库。
- Firebase。
- 自建 PocketBase。

第一版不实现云同步，但不能把数据结构写死为只能单设备使用。

## 技术方案

建议技术栈：

```text
Vite
React
TypeScript
IndexedDB + Dexie
vite-plugin-pwa 或 Workbox
轻量 CSS 或 Tailwind CSS
JSON / CSV 导入导出
```

部署方式：

- 第一阶段可本地运行。
- 后续可部署到 Cloudflare Pages、Vercel 或 GitHub Pages。

## 验收标准

第一版完成时，应满足：

1. 安卓 Chrome 可打开并添加到主屏幕。
2. 无网时仍可打开应用并查看已有数据。
3. 可以新增、编辑、删除咖啡豆。
4. 可以新增、编辑、删除冲煮记录。
5. 可以根据新豆信息生成相似历史记录推荐。
6. 可以导出轻量 JSON 备份。
7. 可以从 JSON 备份恢复。
8. 可以导出 CSV。
9. 默认备份不包含图片。
10. 完整备份可选包含压缩图片。
11. 首页能显示上次备份时间和超期提醒。

## 新手执行顺序

第一步不是写代码，而是确认这份设计是否准确表达需求。

确认后再进入实施计划，实施计划会把任务拆成更小的步骤，例如：

1. 初始化项目。
2. 建立数据模型。
3. 做豆仓页面。
4. 做冲煮记录页面。
5. 做备份导出和恢复。
6. 做 PWA 离线与安装。
7. 做相似豆推荐。
8. 在安卓手机上验证。
