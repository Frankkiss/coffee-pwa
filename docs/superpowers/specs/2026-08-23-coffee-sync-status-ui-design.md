# 咖Day 同步状态 UI 精简设计

## 目标

同步状态应持续可见，但成功状态不应抢占首页内容的视觉层级。用户需要一眼确认数据安全，同时只有在需要操作时才看到完整提示。

## 状态层级

### 已同步

- 使用右对齐的轻量状态胶囊，不再占满内容宽度。
- 默认只显示 `✓ 已同步 · HH:mm`。
- 点击或键盘展开后显示完整同步时间与当前网络能力说明。
- 使用低饱和咖啡绿、暖白底色和细描边，不使用大面积阴影。

### 同步中

- 保留紧凑横向状态条，显示正在检查云端或待同步数量。
- 使用轻量旋转标记，并尊重 `prefers-reduced-motion`。

### 离线、等待重试和保护模式

- 使用完整宽度提示条，明确说明当前限制和待处理数量。
- 仅在可安全重试时显示重试按钮。

### 需要处理

- 保留完整错误提示、数据预览和确认操作。
- 不降低危险色的识别度，不隐藏恢复和放弃操作。

## 交互与响应式

- 成功胶囊至少提供 44px 点击高度、清晰焦点环和可读的 `aria-label`。
- 桌面端靠右显示；窄屏端仍靠右，但不得遮挡或挤压页面主要导航。
- 详细信息通过原生渐进披露呈现，无 JavaScript 动画依赖。
- 状态变化继续通过现有 `aria-live` 区域播报。

## 实现边界

- 只调整 `SyncStatusBanner` 的成功态结构和同步状态 CSS。
- 不修改同步状态机、数据库、队列、重试或恢复逻辑。
- 不引入新依赖，不改变其他页面组件。

## 验证

- 单元测试覆盖成功态的紧凑文案和完整时间详情。
- 现有异常态和重试行为测试必须继续通过。
- 运行完整前端测试和生产构建。
- 在桌面宽度和约 390px 手机宽度下检查布局、焦点和展开行为。
