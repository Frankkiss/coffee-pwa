# 冰手冲粉水比统一设计

## 一、问题与决定

现有实现把冰手冲粉水比定义为 `(热水量 + 冰量) ÷ 粉量`，并把该口径同时用于记录保存、历史分析、模板、规则推荐和 AI 配方校验。该定义把萃取用热水与冷却用冰混为一个比例，导致记录摘要、规则说明和推荐参数都产生误导。

冰手冲从本设计起统一使用以下定义：

`粉水比 = 热水量 ÷ 粉量`

冰量是独立配方参数，只参与冷却、成品稀释、允许范围和步骤终点校验，不参与粉水比计算。热手冲与冷萃继续使用水量除以粉量；意式继续使用液重除以粉量。

## 二、记录录入与旧数据兼容

- 冰手冲新增或编辑记录时，用 `water_grams ÷ coffee_grams` 生成并保存 `ratio`。
- 冰手冲界面把比例标注为“粉水比（仅热水）”，冰量单独显示。
- 读取已有冰手冲记录时，只要粉量和热水量有效，摘要、详情和推荐上下文都实时按新口径重算；不得优先使用旧记录中按总液体保存的 `ratio`。
- 不进行数据库迁移或全量覆盖，不改变旧记录原始字段。用户以后编辑并保存该记录时，才自然写入新口径的 `ratio`。
- 缺少粉量或热水量的旧冰手冲记录不能猜测比例；它只能作为参考，不能成为规则基础。

## 三、系统模板与规则推荐

两个冰手冲系统模板改为显式热水口径：

- Orea Flash：15g 粉、150g 热水、75g 冰，粉水比 `1:10`。
- Seven Miles 1:7:7：15g 粉、105g 热水、105g 冰，粉水比 `1:7`。

冰手冲的全局安全范围改为热水口径 `1:7–1:12`，覆盖两个经过确认的系统模板，不能继续复用热手冲的 `1:14–1:18` 范围。模板和历史来源仍在该安全范围内使用其当前比例上下各 `0.5` 的局部允许范围，避免 AI 把 `1:7` 与 `1:10` 任意互换。

规则改变冰手冲比例时，以新比例重算热水量，并保留原配方的冰量占总液体比例；冰量继续受冰手冲允许范围约束。规则说明必须明确比例只指热水，并把冰量及预计总液体分开解释。

## 四、AI 输入与安全边界

- 前端发送给 `recommend-brew` 的冰手冲 `recipe.ratio` 和 `allowedRanges.ratioDenominator` 使用热水口径。
- 前端与 Edge Function 的重量一致性校验使用 `waterGrams ÷ coffeeGrams` 对照比例，不再使用 `(waterGrams + iceGrams) ÷ coffeeGrams`。
- 冰手冲步骤仍分别要求最后一个 `water` 目标等于 `waterGrams`、最后一个 `ice` 目标等于 `iceGrams`。
- DeepSeek 提示词必须明确“粉水比仅指热水，冰量独立”，避免模型在说明中重新合并两者。
- AI 输出仍只能作为草稿，所有模式、器具、研磨、范围和步骤边界保持不变。

## 五、测试与验证

修复必须先用失败测试覆盖：

1. 冰手冲表单以 15g 粉、150g 热水、90g 冰保存为 `1:10`。
2. 旧记录即使保存了冲突比例，也以有效粉量和热水量派生新比例。
3. 两个冰手冲模板分别生成 `1:10` 与 `1:7`，热水量和冰量与模板说明一致。
4. 规则调整后，比例等于热水量除以粉量，冰量保持独立且总液体内部一致。
5. 前端和 Edge Function 接受符合热水口径的冰手冲 AI 配方，拒绝把冰量算进比例的结果。
6. 记录摘要、规则说明和 AI 提示词明确“仅热水”。
