# 备份导入恢复点 v1 设计

## 目标

在用户导入 JSON 备份前，自动下载一份当前云端数据的恢复点文件，降低误导入、导入异常或数据混乱时的恢复风险。

## 范围

本版本只做导入前恢复点：

- 用户点击“确认导入非重复数据”后，应用先读取当前云端豆仓和冲煮记录。
- 使用现有备份文档结构生成恢复点 JSON。
- 自动下载恢复点文件。
- 恢复点下载完成后，再执行导入。
- 导入成功文案明确说明已经先下载恢复点。

本版本不做：

- 一键回滚。
- 云端保存恢复点文件。
- 完整覆盖导入。
- 图片恢复点。

## 文件命名

恢复点文件名使用：

`coffee-restore-point-YYYY-MM-DD.json`

该文件结构与普通 `coffee-backup-YYYY-MM-DD.json` 相同，仍然可以通过现有 JSON 导入流程恢复。

## 导入流程

1. 用户选择 JSON 文件。
2. 应用读取并展示导入预览。
3. 用户点击“确认导入非重复数据”。
4. 应用读取当前云端数据。
5. 应用下载恢复点 JSON。
6. 应用构建非重复导入 payload。
7. 应用写入 Supabase。
8. 状态提示导入数量、跳过数量和恢复点文件名。

## 失败处理

- 如果导入前无法读取当前云端数据或无法生成恢复点，不继续导入。
- 用户看到错误后可以稍后重试。
- 恢复点不写入默认备份提醒，因为它是导入安全文件，不等同于用户主动定期备份。

## 测试

新增或更新测试：

- 恢复点文件名能按日期生成。
- 恢复点仍使用版本化备份文档结构。
- 导入前恢复点流程保持当前数据和导入数据分离。
