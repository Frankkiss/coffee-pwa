# Coffee PWA AI 来源解析与冲煮推荐

## 架构和安全

来源解析和冲煮推荐都通过带 JWT 验证、用户认证、数据库限流、输入上限和日志脱敏的 Supabase Edge Function 调用 DeepSeek。两个函数统一读取服务端 Secret `DEEPSEEK_VISION_API_KEY`，调用 `deepseek-v4-flash-vision-exp`；Key 不进入前端、浏览器存储、Git、构建产物或响应。

`import-source` 可以发送文字和图片内容块；`recommend-brew` 只发送规则阶段产生的有界结构化文字上下文。两条路径都不得让模型直接写入正式用户数据。

## 来源解析

用户可以提交商品详情文字、一张包装图片或两者组合。前后端都限制 MIME、文件大小和请求体；服务端拒绝 `url` 字段并且不执行网页请求。图片仅用于本次解析，不持久化。

模型输出被严格归一化为豆子字段草稿。无法确认的信息留空，不编造比例、日期或产地。草稿回填表单后必须由用户检查和确认，才能通过豆仓 Repository 保存。

## 推荐流程

1. 用户选择豆子、冲煮方式、器具和磨豆机；冷萃另选直接饮用或浓缩基底。
2. 本地规则从同方式历史和兼容模板中选择基础来源。
3. 规则根据豆子元数据、烘焙新鲜度和历史反馈生成确定性基础配方及允许范围。
4. Edge Function 把基础配方、证据、允许范围和少量历史事实交给 DeepSeek 优化。
5. 客户端验证结构、范围、质量守恒、步骤时序和最终目标。
6. AI 不可用、超时或验证失败时显示规则基础方案；成功时显示 AI 优化草稿。
7. 用户可以把建议转换成冲煮表单草稿，确认后才保存正式记录。

规则决定边界，AI 负责解释、在边界内微调和把步骤写得更可执行，不能任意更换冲煮方式或基础模板。

## 输入与排除项

推荐可使用：

- 豆子袋级产地、庄园或处理站、品种、处理法、烘焙度、烘焙日期和风味标签；
- 用户选择的规范化冲煮方式与冷萃子类型；
- 本次器具和磨豆机；
- 同方式历史配方、评分、风味标签和大白话反馈；
- 兼容系统模板和用户模板。

不得进入规则评分或 AI 请求：

- 剩余豆量；
- 拼配组成、内部比例和拼配说明；
- 来源网址、图片原文或图片 URL；
- 全量历史、其他用户数据、密钥或内部同步字段。

## 四类方式和范围

规则使用显式 `brewMode`，不依赖模板 ID 或模糊文本猜测：

| 方式 | 粉水/液比允许包络 | 主要计量 |
| --- | --- | --- |
| 热手冲 | 1:14–1:18 | 粉量、水量、水温、时间 |
| 冰手冲 | 1:7–1:12，仅热水 | 粉量、热水量、冰量、水温、时间 |
| 冷萃直接饮用 | 1:12–1:16 | 粉量、水量、温度、浸泡时间 |
| 冷萃浓缩基底 | 1:5–1:10 | 粉量、水量、温度、浸泡时间，饮用冰量可选 |
| 意式 | 1:1.5–1:3 | 粉量、杯中出液量、水温、萃取时间 |

冰手冲比例和派生水量永远只按热水计算，冰量单独传输、展示和验证。历史参考、模板、规则卡、AI Prompt、AI 输出和草稿转换必须使用同一语义。

## 历史与模板排序

候选只来自目标方式；冷萃还必须匹配子类型。优先级为：同一豆子的高质量完整历史、相似豆高质量历史、用户模板、系统模板、方式基础规则。

历史相似度可使用处理法、产地、庄园或处理站、品种、烘焙区间、风味和设备兼容性。评分用于排序，但不得让缺少关键配方字段的高分记录成为基础配方。界面展示的参考历史必须从原始记录重新推导规范比例，不能读取旧缓存字符串。

## 大白话反馈

用户直接记录“偏酸、偏苦、发涩、太淡、太浓、甜感好、香气好、干净、余韵短”等自然语言，不要求填写酸甜苦分数。确定性词典先提取低风险信号；联网时 AI 可以补充解析，但结果只用于下一次推荐上下文，不回写或覆盖原始反馈。

冲突信号保留原文并降低调整幅度。单次反馈只允许小幅修改研磨、水温、比例、时间或扰动；必须说明调整依据，不能同时大幅改变多个变量。

## 结构化输出与步骤安全

输出包含摘要、方式、器具、磨豆机、比例、粉量、水量或出液量、冰量、水温、研磨、总时间、分段步骤、推荐理由和下一次调整方向。

校验必须保证：

- 数字有限并落在规则允许范围；
- 方式、子类型和设备不被 AI 改换；
- 分段开始/结束时间单调，总时间与最后一步一致；
- 累计注水、冰量或出液目标不倒退并到达配方总量；
- 冰手冲和冷萃浓缩的冰量不混入萃取水量；
- 比例、粉量、水量和出液量质量守恒；
- 文本步骤不得覆盖结构化数值事实。

无效 AI 结果整体降级到规则方案，不进行危险的部分拼接。

## 超时和降级

高推理模式允许更长、但有上限的响应窗口和输出预算。客户端超时、函数超时、模型未配置、上游错误、JSON 不完整或校验失败都必须显示明确但不泄露内部信息的降级状态，并继续提供规则基础方案。

已保存建议可以离线查看。AI 建议、来源解析和反馈解析均不得自动生成正式豆子、模板或冲煮记录。
